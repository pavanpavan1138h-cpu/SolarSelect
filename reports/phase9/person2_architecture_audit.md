# Person 2 pre-implementation architecture audit

Inspected current repository on 2026-11-11 before implementation, including every file requested in section 0 of the assignment, related Phase 7/8 tests, and feature preprocessing definitions.

- `docs/project/phase_completion_status.md` records Phase 7 complete, Phase 8 complete with limitations, Phase 9 in progress. Root `README.md` still describes Phase 7 design and Phase 8/9 pending; it is stale. Existing user changes/untracked Phase 8/9 work must be preserved.
- `models/phase5/final_model_metadata.json` and `docs/machine_learning/final_model_reference.md` identify the frozen peer ExtraTrees at `models/phase5/final/peer_cohort/final_extra_trees.joblib`, 29 features, daily specific yield in kWh/kWp/day. Primary offline test MAE/RMSE/R2: 0.905/1.07/0.258. The Prompt 1 application report instead names an obsolete artifact path; use actual metadata.
- `src/energy_economics/inference.py` offers `Phase5PeerCohortPredictor`, `validate_features`, `predict`, `get_provenance`. Estimator `feature_names_in_` controls order; fallback requires explicit enum selection. Important gap versus the assignment's verified-facts wording: hashes are computed, not compared with a pinned expected manifest, and metadata names are not cross-checked. The HTTP provider will add these checks outside the frozen engine. Lower-layer target dropping and numeric coercion require stricter HTTP contracts. Negative predictions must remain raw.
- `src/energy_economics/types.py`, `exceptions.py`, `engine.py`, `historical_replay.py` expose scenario-aware public engines and governance enums. No model fitting belongs here. Optional economics/recommendation HTTP routes are deferred: full cost/electrical/scenario contracts need separate scope; required inference/catalogue/geometry routes suffice.
- `src/roof_fit/engine.py` exposes `run_dict`; `roof_validator.py` validates integer-domain usable space, bounds and obstacle uniqueness. Actual fields `clamping_gap`, `walkway_gap`, `allowed_orientations` differ from `app/backend/schemas.py` fields `inter_panel_clearance`, `inter_row_clearance`, `orientation_override`. Introduce a separate HTTP contract with explicit mapping and preserve existing schemas. Do not relax quantization or placement constraints. The engineering input/output document remains marked draft; implementation is authoritative.
- `src/energy_economics/catalogue.py` preserves missing values as None and exposes immutable `PanelRecord.to_dict()`. `configs/panels_catalogue.csv` contains 12 records, including PNL-TRINA-330W. Pricing remains null; original datasheet authentication remains qualified.
- `app/backend/services.py` is a direct-Python Streamlit boundary, with a static offline system-status dictionary, not HTTP readiness. `app/frontend/main.py` and `pages/roof_config.py` retain six-page shell behavior. No frontend changes are required. Service limitations are reusable with additions for geography and geometric-only approval.
- `tests/test_phase8_stage2_inference_and_replay.py` explicitly tests unclipped negative yield, explicit blend, feature ordering, preserved capacity, partial periods and B-2. `tests/test_phase9_app_foundation.py` covers service/schema compatibility and all six Streamlit pages. Existing tests will remain unchanged.
- `src/prepare_phase3_data.py` and prepared `feature_dictionary.csv` define extraterrestrial radiation as kWh/m2/day, whereas `docs/data/data_dictionary.md` says MJ/m2/day. HTTP field documentation will follow actual preprocessing without transforming values. Historical prepared rows may contain earlier preprocessing imputation; this API will not manufacture prospective lag values.
- Root requirements currently list neither API/test dependencies nor existing Streamlit/Plotly dependencies. Python is absent from PATH; bundled Python 3.12.14 is available. Use an isolated repository virtual environment; inspect artifact sklearn serialization version before installing a compatible version.

Selected dependency direction: HTTP routers -> prediction/roof adapters -> existing inference/catalogue/roof libraries. Lifespan initializes a selected provider once; injection supports deterministic stubs. Local source only by default. Future registry source must fail readiness without a verified handoff, with no silent local fallback. Trusted hashes are pinned to audited current bytes in a backend manifest, without altering model artifacts. Registry contents will be inspected read-only before final reporting.
